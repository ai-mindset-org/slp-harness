# Имена файлов

`{тип} описание – ГГГГ-ММ-ДД.md`. Дата в конце, если файл про событие.

| тип | папка | пример |
|---|---|---|
| `{context}` | `context/` | `{context} паспорт комплекса.md` · `{context} конкурент Сандуновские бани.md` · `{context} сегмент пары.md` |
| `{source}` | `sources/` | `{source} отзывы – сентябрь 2026.md` |
| `{meeting}` | `meetings/` | `{meeting} планёрка – 2026-10-05.md` |
| `{ask}` | `asks/` | `{ask} что обещали корпоративному клиенту.md` |
| `{rule}` | `rules/` | `{rule} цены и бронь.md` |
| `{role}` | `people/` | `{role} администратор.md` |
| `{tool}` | `tools/` | `{tool} exa.md` |
| `{task}` | `tasks/` | `{task} меню корпоратива – 2026-10-08.md` |
| `{check}` | `checks/` | `{check} git и приватные данные.md` |
| `{routine}` | `routines/` | `{routine} после встречи.md` |
| `{dashboard}` | `dashboards/` | `{dashboard} прайсинг.html` |
| `{guide}` | `guides/` | `{guide} как развернуть у себя.md` |

Типов двенадцать, и они общие для любой компании. Отдельный тип заводится только для того, что в этой компании главное и чего много; всё остальное – `{context}`, а вид карточки – первое слово имени: конкурент, сегмент, канал. Одна папка – один тип. Ссылки между файлами – обычные markdown-ссылки вида `[название](../папка/файл.md)`: по ним переходят GitHub, Obsidian и агенты.

Журнал агентов в `sessions/` пишется сам: каждый запуск агента – файл `{session} шаг NN агент – дата.md`. Это след работы, отдельным типом папки его не считают.

## как родилось правило
1. **хаос первых недель.** Администратор сохраняет всё как придётся: «Новый документ (3).docx», «прайс ФИНАЛ.xlsx», «прайс финал новый!!.xlsx», «планёрка 5 окт.txt», «IMG_4471.jpg» (фото чек-листа). Управляющий называет по-своему: «Встреча с банщиками 07.10», «меню чая нов». Через месяц в папке 60 файлов, и никто не знает, какой прайс действует.
2. **агент замечает повторы.** Секретарь разбирает папку и пишет в asks/ запрос на решение: «Нашёл 4 вида записи даты (5 окт, 07.10, 2026-10-07, 7.10.26), 3 слова для прайса (прайс, цены, тарифы) и 9 файлов без даты. Предлагаю шаблон».
3. **шаблон предложен.** Агент приносит шаблон «{тип} описание – ГГГГ-ММ-ДД.md»: тип из 12 типов папки (meeting, rule, task, source), дальше короткое описание без пробелов-повторов, дата ISO в конце. Рядом 6 примеров на реальных файлах комплекса и таблица «что куда».
4. **владелица утверждает.** Владелец читает пример, правит одно слово («прайс» вместо «tariff») и пишет в asks/: «утверждаю». В rules/ появляется файл «{rule} имена файлов.md» с шаблоном, списком типов, запретом на слова final и новый, и примерами.
5. **переименование и контроль.** Постановщик создаёт задачу, секретарь переименовывает старые файлы одним коммитом (git mv, история сохраняется), проверяющий читает имена каждого нового файла и ругается на нарушения при каждой проверке перед коммитом. Через неделю агент добавляет в правило исключения, которые встретил в жизни (фото с телефона получают имя по дате съёмки).

## на чём стоит
- Правило имени фиксируется как шаблон из 3–5 элементов метаданных, а порядок элементов выбирается под сортировку и поиск (Caltech Research Data Management Workbook). [источник](https://software.library.caltech.edu/RDMworkbook/file-organization-and-naming.html)
- Дата идёт в формате ISO 8601 (YYYY-MM-DD) в начале или в конце, тогда файлы сортируются по времени и компьютер читает дату одинаково (UW-Madison Libraries). [источник](https://learn.library.wisc.edu/research-data-management/lesson-2/)
- Слова final, final_final и draft множатся. Версию обозначают номером v01 или датой, с ведущими нулями для верной сортировки (UW-Madison Libraries). [источник](https://learn.library.wisc.edu/research-data-management/lesson-2/)
- Имя короткое, но описательное, без спецсимволов; схему имён записывают в readme в корне папки, чтобы её видели люди и программы (University of York). [источник](https://subjectguides.york.ac.uk/rdm/organising)
